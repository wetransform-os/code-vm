# Release Process Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a maintainer cut a versioned GitHub release of `code-vm`, with Linux amd64 and macOS arm64 archives and checksums, by running a manual workflow.

**Architecture:** The binary carries a version injected through `-ldflags -X`. A shell script cross-compiles and packages both targets into `dist/release/`. mise tasks wrap the script to meet the shared `mise-release` workflow's conventions (`ci:verify-release`, `ci:set-version`). `.wetf-ci.yml` declares the release assets. The workflow file itself is generated by github-bootstrap after `.wetf-repo.yml` opts in.

**Tech Stack:** Go 1.26 / cobra, bash, mise tasks (with `usage` flags), semantic-release through `wetransform/gha-workflows` `mise-release.yml`, github-bootstrap.

**Spec:** `docs/superpowers/specs/2026-10-27-release-process-design.md`

## Global Constraints

- Targets: exactly `linux/amd64` and `darwin/arm64`, built with `CGO_ENABLED=0`.
- Archive name: `code-vm_<version>_<os>_<arch>.tar.gz`, version without leading `v`. Contents at the archive root: `code-vm` (mode 0755), `LICENSE`, `README.md`.
- `checksums.txt`: SHA-256 for every archive, in `sha256sum` format, with bare file names.
- Output directory: `dist/release/` (under the git-ignored `dist/`).
- `code-vm --version` prints the stamped version. Unstamped builds report `dev`.
- Release binaries differ from `mise run build` only in the stamped version and the target platform: same `go build` flags otherwise.
- Required mise task names: `ci:verify-release`, `ci:set-version` taking `--version <version>`.
- `.wetf-repo.yml` presets: exactly `mise` and `workflows-release`.
- Commits follow Conventional Commits. There is no JIRA issue for this branch, so the footer has none. No `Co-authored-by`.
- New shell must pass `shellcheck` and `shfmt` (the `lint` and `fmt-check` tasks must cover it).

## Review Focus

1. **Leftovers from a previous run in `dist/release/`.** Expected: the script empties the directory first, so old archives are never checksummed or uploaded. Test: Task 2, Step 4c.
2. **A version passed with a leading `v` (`v1.2.3`) or with no version at all.** Expected: the script fails with a clear message and writes nothing. It must not produce `code-vm_v1.2.3_…` or `code-vm__…`. Test: Task 2, Step 4b.
3. **`checksums.txt` lists paths instead of bare names**, so `sha256sum -c` fails after a user downloads the files into one directory. Expected: verification passes from inside the directory. Test: Task 2, Step 4a.
4. **Darwin binary built for the wrong arch, or with cgo.** It can't be run on the Linux runner, so this would go unnoticed. Expected: `go version -m` shows `GOOS=darwin`, `GOARCH=arm64`, `CGO_ENABLED=0`, and the version ldflag. Test: Task 2, Step 4a.
5. **`--version` alongside the root command's passthrough/arg guard.** Expected: `code-vm --version` prints the version and never boots or enters the VM. Test: Task 1, Step 1, which runs the command through `NewRootCmd().Execute()`.

### Task 1: Version stamping

**Files:**
- Create: `internal/cli/version.go`
- Modify: `internal/cli/root.go` (set `Version` on the root command in `NewRootCmd`)
- Test: `internal/cli/version_test.go`

**Interfaces:**
- Produces: package variable `version string` in `github.com/wetransform/code-vm/internal/cli`, default `"dev"`, set at link time with
  `-ldflags "-X github.com/wetransform/code-vm/internal/cli.version=<version>"`. Task 2 uses exactly this symbol path.

- [ ] **Step 1: Write the failing tests** in `internal/cli/version_test.go`

```go
// Unstamped builds must say so instead of claiming a release version.
func TestVersionFlagReportsDevWhenUnstamped(t *testing.T) {
	out := runVersion(t)
	if out != "code-vm version dev\n" {
		t.Errorf("--version output = %q, want %q", out, "code-vm version dev\n")
	}
}

// The ldflags-stamped value is what --version reports.
func TestVersionFlagReportsStampedVersion(t *testing.T) {
	old := version
	version = "1.2.3"
	t.Cleanup(func() { version = old })
	if out := runVersion(t); out != "code-vm version 1.2.3\n" {
		t.Errorf("--version output = %q, want %q", out, "code-vm version 1.2.3\n")
	}
}
```

`runVersion(t)` builds `NewRootCmd()`, sets its out to a `bytes.Buffer`, sets the args to `[]string{"--version"}`, calls `Execute()`, fails the test on error, and returns the buffer contents. If `--version` fell through to `RunE`, `runDefault` would try to load config/boot the VM and return an error, so the error check covers Review Focus 5.

- [ ] **Step 2: Run the tests to verify they fail**

Run: `go test ./internal/cli -run TestVersionFlag -v`
Expected: build failure, `undefined: version`.

- [ ] **Step 3: Implement**

`internal/cli/version.go`: a doc comment saying release builds override the variable with `-ldflags -X` (giving the full symbol path), and `var version = "dev"`. In `NewRootCmd`, set `Version: version` in the `cobra.Command` literal. Cobra's default template, `code-vm version <v>`, is fine; don't customize it.

- [ ] **Step 4: Run the tests to verify they pass, then the full unit suite**

Run: `go test ./internal/cli -run TestVersionFlag -v && mise run test:unit`
Expected: PASS.

- [ ] **Step 5: Manual check of the ldflags path**

Run: `go build -ldflags "-X github.com/wetransform/code-vm/internal/cli.version=9.9.9" -o dist/code-vm ./cmd/code-vm && ./dist/code-vm --version`
Expected: `code-vm version 9.9.9`

- [ ] **Step 6: Commit**

```bash
git add internal/cli/version.go internal/cli/version_test.go internal/cli/root.go
git commit -m "feat: report the build version with --version"
```

### Task 2: Release packaging and mise tasks

**Files:**
- Create: `scripts/release-build.sh`
- Create: `.wetf-ci.yml`
- Modify: `mise.toml` (new tasks, and add `scripts/*.sh` to the `lint` shellcheck and `fmt-check` shfmt invocations)

**Interfaces:**
- Consumes: the ldflags symbol `github.com/wetransform/code-vm/internal/cli.version` from Task 1.
- Produces:
  - `bash scripts/release-build.sh <version>`: exits non-zero without touching `dist/release/` when `<version>` is missing or doesn't match `^[0-9]+\.[0-9]+\.[0-9]+([-+][0-9A-Za-z.+-]+)?$`. Otherwise it recreates `dist/release/` and writes the two archives and `checksums.txt`.
  - mise task `release:build --version <v>` (for local use) and `ci:set-version --version <v>` (for the shared workflow). Both run the script with the flag's value.
  - mise task `ci:verify-release`: depends on `fmt-check`, `lint`, `test:unit`.

- [ ] **Step 1: Write `scripts/release-build.sh`**

`set -euo pipefail`, then run from the repository root (`cd "$(dirname "$0")/.."`). Validate the argument (see Interfaces) and fail with `usage: release-build.sh <version>` (or `invalid version "<v>": expected semver without leading v`) on stderr. Next, `rm -rf dist/release` and recreate it. For each of `linux/amd64` and `darwin/arm64`: run `CGO_ENABLED=0 GOOS=… GOARCH=… go build -ldflags "-X github.com/wetransform/code-vm/internal/cli.version=$version" -o <staging>/code-vm ./cmd/code-vm`, copy `LICENSE` and `README.md` into the staging directory, and `tar -czf dist/release/code-vm_${version}_${os}_${arch}.tar.gz -C <staging> code-vm LICENSE README.md`. Use a staging directory under `dist/` and remove it on exit with a trap. Finally, from inside `dist/release`, run `sha256sum code-vm_*.tar.gz > checksums.txt`. Use no other `go build` flags (Global Constraints).

- [ ] **Step 2: Add the mise tasks and lint coverage to `mise.toml`**

Both version-taking tasks declare the flag through mise's `usage` field, so `mise run ci:set-version --version X` parses it:

```toml
usage = 'flag "--version <version>" help="Release version, without leading v" required=#true'
run = 'bash scripts/release-build.sh "${usage_version}"'
```

`ci:verify-release` uses `depends = ["fmt-check", "lint", "test:unit"]` with no `run` of its own. Give each task a `description`. Add `scripts/*.sh` to the `shellcheck` line in `lint`, and add `scripts` to the `shfmt -d` line in `fmt-check`.

- [ ] **Step 3: Write `.wetf-ci.yml`**

```yaml
release:
  assets:
    - path: dist/release/*.tar.gz
    - path: dist/release/checksums.txt
```

- [ ] **Step 4: Verify**

a) Run `mise run release:build --version 0.0.0-test`, then:
- `ls dist/release` → exactly `checksums.txt`, `code-vm_0.0.0-test_darwin_arm64.tar.gz`, `code-vm_0.0.0-test_linux_amd64.tar.gz`
- `(cd dist/release && sha256sum -c checksums.txt)` → both `OK`
- `tar -tzvf dist/release/code-vm_0.0.0-test_linux_amd64.tar.gz` → exactly `code-vm` (`-rwxr-xr-x`), `LICENSE`, `README.md`, with no directory prefix
- extract the linux archive into a scratch directory and run `./code-vm --version` → `code-vm version 0.0.0-test`
- extract the darwin archive and run `go version -m code-vm` → contains `GOOS=darwin`, `GOARCH=arm64`, `CGO_ENABLED=0` and `-X github.com/wetransform/code-vm/internal/cli.version=0.0.0-test`

b) Each of these must exit non-zero with the usage/invalid-version message, and must leave the listing from (a) unchanged:
- `bash scripts/release-build.sh`
- `bash scripts/release-build.sh v1.2.3`
- `bash scripts/release-build.sh latest`

c) Run `touch dist/release/stale.tar.gz && mise run release:build --version 0.0.0-test2`, then `ls dist/release` → only the three `0.0.0-test2` files, with no `stale.tar.gz` and nothing from `0.0.0-test`.

d) Run `mise run ci:set-version --version 0.0.0-test3` → the same three files for `0.0.0-test3`. This confirms the exact call the shared workflow makes.

e) Run `mise run ci:verify-release && mise run lint && mise run fmt-check` → all pass, with the new script included in the lint and format checks.

- [ ] **Step 5: Commit**

```bash
git add scripts/release-build.sh mise.toml .wetf-ci.yml
git commit -m "build: package release archives for linux/amd64 and darwin/arm64"
```

### Task 3: Enable the managed release workflow and document installing

**Files:**
- Create: `.wetf-repo.yml`
- Modify: `README.md` (new `## Install from a release` section directly before `## Quick start`. Quick start keeps the build-from-source steps. Add a short "Releasing" subsection under `## Testing`, or a new `## Releasing` section after it.)

**Interfaces:**
- Consumes: archive and checksum names from Task 2, and `--version` output from Task 1.

- [ ] **Step 1: Write `.wetf-repo.yml`**

```yaml
---
# Repository configuration for wetransform managed repositories
# (applied by wetransform/github-bootstrap)

presets:
  - mise
  - workflows-release
```

Add a comment noting that `workflows-default` is left out on purpose: `ci.yml` covers checks, and no publish workflow is wanted.

- [ ] **Step 2: Write the README sections**

"Install from a release" covers:
- downloading the archive for your platform plus `checksums.txt` from the GitHub releases page, running `sha256sum --ignore-missing -c checksums.txt` (or `shasum -a 256 --ignore-missing -c checksums.txt` on macOS), extracting, and running `sudo install -m 0755 code-vm /usr/local/bin/code-vm`
- `mise use -g github:wetransform-os/code-vm`. The repository is public, so no token is needed.
- the supported platforms: Linux x86_64 and macOS on Apple Silicon. Other platforms build from source.
- macOS: binaries are unsigned. A browser download is quarantined by Gatekeeper; clear it with `xattr -d com.apple.quarantine code-vm`, or allow it in System Settings → Privacy & Security. Downloads with curl or mise are not affected.
- checking the installed version with `code-vm --version`

"Releasing" (for maintainers) covers: run the **Release** workflow in GitHub Actions on `main`, with **Dry-Run** checked first to preview the version and notes. The version comes from conventional commits (`feat` → minor, `fix` → patch, breaking change → major), and a release with no `feat`/`fix`/breaking commits since the last one is skipped. Local packaging check: `mise run release:build --version 0.0.0-test`.
